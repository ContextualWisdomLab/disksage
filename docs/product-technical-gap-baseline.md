## Product invariants

1. Scan and classification are read-only until a separately authorized reclaim boundary is reached. Logical size, allocated size, filesystem identity, active use, materialization, provider state, ontology labels, and model advice are distinct evidence.
2. User-file removal is reversible and journaled. Permanent general user-file deletion is not a supported DiskSage action.
3. Regenerable-cache policy never grants irreversible authority merely from names, signatures, byte counts, or approval phrases. Shipped permanent execution fails closed when identity-bound capability is unavailable.
4. A successful mutation must consume the exact reviewed object. Repeating pathname checks is not sufficient authority for replacement or irreversible deletion.
5. Cloud copy, provider sync proof, local presence, local eviction, and source removal are separate transitions. Ambiguous provider/quota/auth/headroom/collision/active-use/placeholder/identity evidence fails closed.
6. Models and ontology may classify, explain, or recommend but cannot override deterministic filesystem/deletion evidence or mutate DiskSage truth. Model-backed repository workflows consume literal `orchestrator/free` through contextual-orchestrator; provider/account/model discovery and failover remain gateway-owned.
7. Settings, receipts, approvals, and recovery records distinguish first-run absence from an existing unreadable or unsafe document. Failed replacement preserves the previous complete value.
8. Crash/power-loss and durability claims are platform-specific and name the primitive actually exercised. macOS `fsync` evidence is not represented as `F_FULLFSYNC` evidence.
9. Shared workflow behavior has one canonical owner. Source-absent conditional success is admission evidence, not runtime proof.
10. Release readiness belongs only to the exact protected lineage after all applicable deterministic, security, model/review, provenance, reproducibility, rollback, and human-governance gates pass. Predecessor success never transfers automatically.
11. Unix child-process cleanup retains a live or waitable identity anchor until every process-group-directed signal is complete. A numeric PID/PGID observed before reaping is not durable signal authority after the leader is consumed. Interrupted `waitid` observation is retried without consuming the child; a genuine non-interrupted observation failure does not authorize signaling an unverified group and must not leave owned reader threads or descriptors unbounded.
12. Browser E2E cleanup is acceptance evidence. The harness requests browser-level graceful shutdown, proves launched-browser exit, then removes its profile; retry widening or ignored cleanup failure cannot manufacture GREEN.
13. UI translation resources and filesystem/ontology labels are separate authorities. Locale text uses versioned screen keys/resource versions; ontology labels cannot silently become presentation-language storage or alter deterministic classification truth.
14. Supported-runtime contracts apply to tests as well as production. A test requiring an experimental runtime capability must enable it at the narrow test boundary only where that supported runtime needs it, or explicitly change the supported runtime through its canonical owner; CI-wide flags and minimum-version bumps are not leaf conveniences.
15. A bundled translation resource is admitted only when its build-pinned resource version, fixed bundle-relative path, SHA-256 digest, declared schema shape, stable screen keys and exact locale set all match. Schema-v1 resources reject undeclared top-level semantics instead of silently discarding them; semantic shape changes require an explicit schema evolution. Digest verification detects changed resource bytes but is not a code-signing substitute, and presentation code cannot promote a caller-selected pathname into translation authority.
16. Presentation IPC may select only an explicit admitted locale and stable screen key. Resource path, version, digest and filesystem authority remain native/build-owned; missing or unsupported presentation data fails explicitly rather than silently selecting another locale or ontology label.
17. Model-routing lifecycle boundaries distinguish connection establishment, provider/model execution, streaming/tool/reasoning progress, user cancellation, and administrative workflow termination. A fixed elapsed-time inference cutoff is not substituted for those distinct states.
18. Accepted ADR meaning is append-only. A later routing, cadence, or owner change uses a fresh Proposed ADR and normal review rather than rewriting an Accepted historical record.

## Standards and owner traceability

- POSIX pathname operations such as `openat()`/`renameat()`/`unlinkat()` bind resolution to directory descriptors but do not by themselves prove that the final name-selected mutation consumed the exact previously reviewed object. Linux `openat2()` adds useful `RESOLVE_*` constraints but does not independently satisfy final-object deletion identity.
- POSIX `waitid()` with `WNOWAIT` can observe an exited child while leaving it waitable. #386 exact `ad61c380...` retries `EINTR` without falling back to `try_wait()` and has terminal Test `34644724901`; other observation errors remain fail closed. #387 exact `a0284e5...` retains that production authority while repairing only the stress-fixture publication shape and has terminal Test `34804708702` SUCCESS. #389 remains terminal exact GREEN. #399 current `a753063...` adds bounded/cancellable reader settlement for genuine non-interrupted observation failure and has terminal Test `34742053282` SUCCESS with a real Linux `ECHILD` fixture; this does not authorize signaling an unverified PGID. #394 is explicitly bound to current #386 authority; #206/#247 remain caller migrations rather than source-copy targets.
- Windows same-object permanent-delete research is tied to handle-oriented semantics: `FILE_ID_INFO` for stable identity and handle-based disposition/rename primitives. DiskSage does not enable this path until descendant, reparse, ACL, partial-progress, crash/recovery, and real NTFS/ReFS evidence exists.
