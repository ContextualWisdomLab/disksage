## Product invariants

1. Scan and classification are read-only until a separately authorized reclaim boundary is reached. Logical size, allocated size, filesystem identity, active use, materialization, provider state, ontology labels, and model advice are distinct evidence.
2. User-file removal is reversible and journaled. Permanent general user-file deletion is not a supported DiskSage action.
3. Regenerable-cache policy never grants irreversible authority merely from names, signatures, byte counts, or approval phrases. `--purge-proven-cache-trash` remains inspection-only and shipped execution fails closed when identity-bound permanent-delete capability is unavailable.
4. A successful mutation must consume the exact reviewed object. Repeating pathname checks is not sufficient authority for replacement or irreversible deletion. Unsupported platform primitives fail before mutation rather than falling back to delete-and-create or recursive pathname deletion.
5. Cloud copy, provider sync proof, local presence, local eviction, and source removal are separate transitions. Stale/incomplete provider evidence, quota/auth/headroom ambiguity, collisions, active use, placeholders, or identity gaps fail closed.
6. Models and ontology may classify, explain, or recommend but cannot override deterministic filesystem/deletion evidence or mutate DiskSage truth. Model-backed repository workflows consume `orchestrator/free` through contextual-orchestrator and do not pin a paid/direct provider locally.
7. Settings, receipts, approvals, and recovery records distinguish first-run absence from an existing unreadable or unsafe document. Failed replacement must preserve the previous complete value.
8. Crash/power-loss and durability claims are platform-specific and must name the primitive actually exercised. macOS `fsync` evidence is not described as stronger `F_FULLFSYNC` evidence.
9. Shared workflow behavior has one canonical owner. Source-absent conditional success is admission evidence, not runtime proof.
10. Release readiness belongs only to the exact protected lineage after all applicable deterministic, security, model/review, provenance, reproducibility, rollback, and human-governance gates pass. Predecessor success never transfers automatically.
11. Unix child-process cleanup must retain a live or waitable identity anchor until every process-group-directed signal is complete. A numeric PID/PGID observed before reaping is not durable mutation authority after the leader is consumed.
12. Browser E2E cleanup is part of acceptance evidence, not disposable teardown. The harness requests browser-level graceful shutdown, proves the launched browser exited, and only then deletes its profile; retry widening or ignored cleanup failure cannot convert a race into GREEN.

## Standards and owner traceability

- POSIX pathname operations such as `openat()`/`renameat()`/`unlinkat()` bind resolution to directory descriptors but do not by themselves prove that the final name-selected mutation consumed the exact previously reviewed directory object. Linux `openat2()` adds strong `RESOLVE_*` path-resolution constraints and remains valuable for inspection/traversal, but does not independently satisfy the final-object deletion invariant.
- POSIX `waitid()` with `WNOWAIT` can observe an exited child while leaving it waitable. DiskSage's #386 shared Unix lifecycle uses that design so the process-group leader is not reaped before descendant-group cleanup; #387 consumes the shared primitive in the container runtime instead of copying it. Exact #386/#387 Tests are GREEN, while protected-lineage integration and broader #385 caller migration remain open.
- Windows same-object permanent-delete research is tied to native handle-oriented semantics. Microsoft documents `FILE_ID_INFO` volume serial + 128-bit file ID as a same-file identity check between open handles, and `SetFileInformationByHandle`/`FILE_DISPOSITION_INFO` as handle-based rename/delete primitives requiring appropriate access. DiskSage does not enable this path until recursive descendant, reparse, ACL, partial-progress, crash/recovery, and real NTFS/ReFS evidence is present.
- macOS persistence claims distinguish ordinary `fsync` evidence from stronger `F_FULLFSYNC` semantics. Portable POSIX name-based final mutation is not promoted to object-bound permanent-delete authority merely because ancestor traversal is descriptor-relative.
- OAuth bearer credentials sent in the `Authorization` header follow RFC 6750 §2.1 syntax. #339 exact `1e3f434...` enforces its admitted ASCII token alphabet/trailing-padding boundary before transport, with exact Test `34506068789` GREEN; downstream branches consume the verified owner delta rather than maintaining a divergent validator.
- Tauri 2's test module provides a MockRuntime path (`mock_builder`, `mock_context`, `WebviewWindowBuilder`, `get_ipc_response`) for invoking registered commands through IPC without a shipped desktop window; the module is gated by Tauri's `test` feature, and Tauri's own test example uses platform-local origins. DiskSage enables the feature only in dev/test dependency scope and preserves custom-command origin checks rather than granting remote IPC authority. This does not substitute for real platform/filesystem evidence where command authority depends on actual OS objects or native adapters.
- GitHub Actions evidence is exact-head evidence only when the relevant source exists and the workflow actually executes it. Failed-job rerun/carry-forward records must not be treated as proof that every reported job physically executed on the same attempt. Compound package scripts require original-invocation evidence before a failed workflow step is attributed to a nested test or browser phase. Cleanup operations in browser evidence must be failure-isolated so one teardown error cannot prevent later cleanup, and cleanup failure must not mask an earlier browser assertion.
- Chrome browser-lifecycle evidence uses the browser-level DevTools endpoint exposed by `/json/version`; page-target CDP is interaction authority but not browser-process shutdown authority. `Browser.close` is requested before process-exit proof and profile removal, while bounded OS signals remain abnormal-startup/shutdown fallback rather than the primary success path.
- For keyboard-operable overflow regions, DiskSage follows the W3C ACT expectation that scrollable content be reachable through sequential focus navigation; preserving a focusable scroll region is therefore an accessibility requirement, not an incidental tabindex side effect.

Central CodeQL/model workflow defects remain canonical `.github` owner work rather than DiskSage leaf substitutes.
